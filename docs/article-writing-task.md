# 記事執筆タスク仕様書（AI執筆向け・別セッション委譲用）

このファイルは、別の作業セッション／エージェントに「育休もらえる？」のガイド記事執筆を依頼するための自己完結した指示書。
人間（ディレクター）が記事ごとに方向性を与え、AIが本文を書く運用を想定する。

## 0. ゴール

`ikukyu-moraeru.github.io`（育児休業給付金の受給判定ツール）に、AdSense審査を通過できる質と量のガイド記事を追加する。
YMYL（お金×公的制度）領域なので、正確性・出典・独自性が最重要。

## 1. 必読の参照元（執筆前に必ず読む）

- `docs/article-plan.md` … 記事一覧と各記事のアウトライン（検索意図・見出し・要点・ツール導線）。**何を書くかの設計図**。
- `Rule.md` … 制度仕様の根拠（厚労省パンフ2025-08-01改訂版／業務取扱要領59523（旧59533） 等）。**事実の出典**。
- `src/domain/*.ts`（eligibility.ts / relaxation.ts / carryOver.ts / completeMonth.ts / types.ts）… ツールが実装している判定ロジック。**記事の主張はこの計算と矛盾させないこと**。

## 2. 出力フォーマット（重要）

1記事 = 1ファイル。`content/guide/<slug>.md` に Markdown で書く。
先頭に frontmatter を置く：

```markdown
---
title: "記事タイトル（検索意図に沿った具体的なもの）"
description: "120字程度のメタディスクリプション。検索結果に出る要約。"
slug: "part-time-shift-jitan"          # ファイル名と一致
date: "2026-06-08"                      # 公開日 YYYY-MM-DD
updated: "2026-06-08"                   # 最終更新日
tags: ["受給要件", "勤務形態"]
related: ["80jikan-rule", "chingin-shiharai-kiso-nissu"]  # 関連記事の slug
draft: false
---

本文（Markdown）。H2/H3 見出し、表、箇条書きを使う。
```

- 画像は原則使わない（著作権グレーなものは厳禁）。必要なら自作の図表・テキストのみ。
- 内部リンク: ツールは `/`、関連記事は `/guide/<slug>/` で書く。
- frontmatter の `related` や本文リンクは、**まだ執筆していない記事の slug を指すと404になる**。既に存在する記事の slug のみリンクし、未執筆ぶんは記事が増えた段階で追記する（または該当記事執筆時に相互リンクを張る）。

## 3. 執筆ディレクティブ

- **構成の型**: ①検索意図への結論を先出し → ②仕組み・理由 → ③具体例（必ず数字入り） → ④「あなたの場合はツールで確認」導線 → ⑤出典 → ⑥関連記事。
- **文字数**: 1,000〜2,000字目安。薄い水増しはしない。
- **文体**: 簡潔・問題解決型。冗長な前置き・AIっぽい定型（「いかがでしたか」等）を避ける。専門用語は初出で噛み砕く。
- **正確性（YMYL）**: 断定しすぎない。数値・要件は `Rule.md`／`src/domain` と一致させ、最終確認は一次情報（厚労省・ハローワーク）へ誘導。各記事末に免責一文（「本記事は参考情報です。最終判定は管轄のハローワークで行われます。」）。
- **出典明記**: 雇用保険法／厚労省パンフ（2025-08-01改訂版）／業務取扱要領59523（旧59533）／80時間ルール LL020615 保01（2020-08-01施行）等、該当箇所を記事内で示す。
- **独自性（AdSense差別化の肝）**: 既存記事が薄い領域（週5正社員以外・延長の正確な仕組み・つわり休職の落とし穴）を、ツールの計算根拠で具体的に書く。一般論の焼き直しにしない。
- **内部リンク**: 本文中から関連記事とツールへ自然に誘導。

## 5. 運用フロー

1. ディレクター（人間）が1記事ぶんの方向性・強調点・想定読者を指示。
2. AIが該当 slug の `content/guide/<slug>.md` を作成（フォーマット遵守）。
3. 人間が数値・要件をファクトチェック（YMYLのため必須）。
4. `pnpm build` で `/guide/<slug>/` に静的HTML化され、sitemapにも反映される（配信の仕組みは `scripts/build-guide.mjs`）。
5. commit / push すると GitHub Actions が自動デプロイし、`https://ikukyu.nkjzm.jp/guide/<slug>/` に公開される。

## 6. プレビュー・確認方法

- ローカル確認: `pnpm build && pnpm preview` → ブラウザで `/guide/<slug>/` や `/guide/` を開く。
- **注意: `pnpm dev` ではガイド記事は表示されない**（ビルド時に生成する静的ページのため）。必ず build → preview で確認する。
- 公開先: 記事 = `/guide/<slug>/`、一覧 = `/guide/`、sitemap = `/sitemap.xml`。
- `pnpm build` 後にコンソールへ「記事 N 本…生成」と出れば取り込まれている。

## 7. やってはいけないこと

- 出典のない断定、`src/domain` の判定と矛盾する記述。
- 他サイト文章のコピー、著作権グレー画像の使用。
- 中身の薄い水増し記事の量産（AdSenseの「有用性の低いコンテンツ」に直結）。
- ツールの入力ウィザード等、非コンテンツ画面への広告設置。
