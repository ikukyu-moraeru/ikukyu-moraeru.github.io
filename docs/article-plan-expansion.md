# 「育休もらえる？」記事拡張プラン（AdSense再申請向け）

2026-06-20 作成。AdSense「有用性の低いコンテンツ」不承認を受けた立て直し用プラン。
既存プラン [`article-plan.md`](./article-plan.md) の続きではなく、**トピックの幅を広げる**ための別軸。

## なぜ作るか（不承認の構造的原因）

既存16記事は良質だが、**実質1テーマに収束している**ことがデータで裏づけられた。

### 重複度チェック結果（2026-06-20 実測）

主要概念が16記事中いくつに登場するか（＝トピックの単調さの指標）:

| 概念 | 出現記事数 | 延べ出現 |
|---|---|---|
| 2年 | 14/16 | 80回 |
| 11日 | 15/16 | 75回 |
| 12か月 | 15/16 | 71回 |
| 賃金支払基礎日数 | 15/16 | 66回 |
| 完全月 | 7/16 | 45回 |
| 80時間 | 11/16 | 43回 |

- **tags は16本中14本が `["受給要件", "緩和"]`** ＝ サイト全体が1テーマ。
- ただし各記事のリード文・切り口（転職・双子・つわり・予定日ぶれ・産前休業短縮…）は全て異なり、**文章レベルの近重複＝コピペ判定リスクは低い**。
- 問題は**トピックレベルの単調さ**。「12か月要件の数え方」の周回で、制度の他領域（金額・申請・延長・社保免除・取り方）がゼロ。AdSenseには「単一機能ツール＋薄い1テーマサイト」に見える。

### 立て直しの方針

1. **育児休業給付金のライフサイクル全体**へ拡張する（要件 → 金額 → 取り方 → 申請 → 延長 → 育休中のお金 → 立場別）。
2. 既存の「受給要件」クラスターは**完成済み資産として温存**し、新カテゴリを積む。
3. 各記事は一次資料に根拠を置き独自性を担保（既存方針を継承）。
4. **文字数は3,500〜5,000字**へ引き上げ（既存の約2,800字は薄め判定の一因）。
5. カテゴリ別ナビ（タグ）で「コンテンツの厚いサイト」に見せる。

## 競合実例による検証（2026-06-20 追記）

AdSenseを**通過済み**の競合サイト [`ikukyu.tokyo-jp.org`](https://ikukyu.tokyo-jp.org/)（育休手取りシミュレーター＋コラム）を実地調査し、本プランの仮説を裏取りした。結論として「**トピックの単調さが不承認の真因**」という診断（[なぜ作るか](#なぜ作るか不承認の構造的原因)）は競合の実例で裏づけられた。

### 数の逆転 — 記事本数は合否要因ではない

| | 当サイト（不承認） | 競合（通過） |
|---|---|---|
| 記事数 | **16本** | **5本** |
| テーマの幅 | 全16本が「受給要件／12か月の数え方」に収束 | 5本が**それぞれ別領域** |
| ツール | 受給要件**判定** | 手取り**シミュレーター**（ママ用/パパ用） |
| タグ表示 | 定義のみ・**未露出** | 💰給付金 👨‍👶パパ 📋準備 🏃‍♀️復帰 と**可視化** |

**記事数で上回りながら不承認**。AdSenseの「有用性の低いコンテンツ」は本数ではなく「サイトが何のサイトか＝トピックの幅」を見ている、という本プランの前提が実証された。

### 競合5本の構成 — 1本＝ライフサイクルの1領域

1. 育休中の手取りはいくら？給付金・社保免除【2026年版】 … **金額**（当プラン M1+M2+M3+T1 を1本に束ねた構成）
2. 産後パパ育休 完全ガイド … **取り方/パパ**（U1）
3. 育休中のボーナスはどうなる？賞与免除 … **社保/育休中のお金**（T1）
4. 産休・育休前にやるべき5つの準備チェックリスト … **準備/申請**（A1系）
5. 育休から職場復帰を成功させる完全ガイド … **復帰**（当プラン未収録の新領域）

各記事は **3,500〜4,000字＋給付率比較表・月給別の具体的試算表**で作り込まれている。当サイトの約2,100〜2,900字・表少なめは、相対的に「薄め」に見える（[立て直しの方針](#立て直しの方針) 4 を補強）。

### E-E-A-T形式要件は不承認の主因ではない

競合は **著者名・監修・一次資料リンクがすべて無く、お問い合わせ・運営者情報ページも無い**。それでも通過している。一方、当サイトは著者表示・一次資料への注釈リンク・content-policyを備える＝**形式的なE-E-A-Tではむしろ当サイトが上**。よって不承認の主因は権威性の不足ではなく、あくまで**トピックの幅と1記事の厚み**。[E-E-A-T補強](#e-e-a-t-補強並行タスクymyl必須)は重要だが、再申請の律速ではない。

### 方針への反映 — 「幅優先・最小4本」を再申請の最短ルートに

段階投入で15本フル投下する前に、競合と同じ「**幅の違う領域を各1本・表と試算込みで約4,000字**」を先行させる方が、再申請までの距離は短い。優先4本の目安:

- M1（金額・手取り） … 競合 `kyufu-kaisetsu` をテンプレに M1+M2+M3+T1 を1本へ束ねる
- U1（産後パパ育休）
- U2（育休延長）
- T1（社会保険料免除）

これに**タグ露出**（[タグ機能の実装](#タグカテゴリ機能の実装) 手順1）を合わせれば、16本の既存資産を「受給要件」カテゴリとして温存したまま、サイトの見え方を「1テーマ」から「育休給付の総合情報サイト」へ転換できる。フルの段階投入（[投入順とマイルストーン](#投入順とマイルストーン)）はその後の流入拡大施策として継続する。

## タグ（カテゴリ）機能の実装

現状、frontmatter の `tags` は**定義されているだけで一切露出していない**（描画コードなし／`dist` HTMLに出力なし）。記事拡張に合わせてタグを「生かし」、サイトをカテゴリで整理された総合情報サイトに見せる。

### 狙い

- 単一テーマ感の解消を**構造として可視化**（要件だけでなく金額・申請・延長…と並ぶことが一目で分かる）
- カテゴリ別の内部リンク網を作り、クロール性と回遊を上げる
- AdSenseが重視する「ナビゲーション要素・トピック別整理」を満たす

### タグ体系（拡張後7系統に再編）

既存の `受給要件`/`緩和`/`基礎知識`/`転職`/`開発ストーリー` は粒度がバラバラなので、カテゴリ用の**第一階層タグ**を1記事1つ付け直す（補助タグは任意で併記可）。

| カテゴリタグ | 対象記事 |
|---|---|
| `受給要件` | 既存16本の大半（現行クラスター） |
| `金額・計算` | M1〜M4 |
| `制度の使い方` | U1〜U3 |
| `申請手続き` | A1〜A2 |
| `育休中のお金` | T1〜T3 |
| `働き方別` | W1〜W2 |
| `開発ストーリー` | naze-tsukutta |

### 実装範囲（最小で効果を出す順）

1. **記事ページにタグ表示**: 本文ヘッダ or フッタにカテゴリのバッジを描画。リンク先はタグ一覧ページ。
2. **タグ一覧ページ `/guide/tag/<slug>/`**: そのタグの記事カードを並べる。SSGの既存ガイド一覧生成ロジックを流用（`scripts/` のビルド処理に追加）。
3. **ガイド一覧 `/guide/` にカテゴリ見出し**: 既存のテーマ別セクションをこのタグ体系に揃える（トップのガイドカード刷新の延長）。
4. **グローバルナビ／フッターにカテゴリ導線**: 主要カテゴリへのリンク。
5. **sitemap にタグ一覧ページを追加**。
6. 構造化データ: タグ一覧ページに `CollectionPage`、各記事に `Article.about`/`keywords` としてタグを反映（任意・E-E-A-T補助）。

### 設計上の注意（破綻条件）

- タグ一覧ページは**実体のある一覧**にする。記事1本だけのタグページや中身の薄いタグページを量産すると、逆に「誘導ページ（ドアウェイ）／薄いページ」と判定されるリスク。**1タグ最低3記事**を目安にし、揃うまでは公開しない。
- タグの乱立を避ける（第一階層は7系統で固定。細分化したくなったら補助タグで吸収）。

## 投入順とマイルストーン

新規は **2〜3か月かけて段階投入**（新規即再申請は不利。更新頻度の実績を作る）。

0. **タグ基盤（先行）**: タグ表示・タグ一覧ページ・sitemap対応を実装（[タグ機能の実装](#タグカテゴリ機能の実装)）。既存16本のカテゴリタグを付け直す。※記事が増える前に器を作っておく
1. **第1弾（金額）**: M1 → M2 → M3 → M4　※検索流入の主力。4本揃ったら `金額・計算` タグページを公開（1タグ3記事以上の原則）
2. **第2弾（取り方・延長）**: U1 → U2 → U3 → `制度の使い方` タグページ公開
3. **第3弾（申請・育休中のお金）**: A1 → A2 → T1 → T2 → T3 → 各タグページ公開。グローバルナビにカテゴリ導線を追加
4. **第4弾（立場別）**: W1 → W2
5. 全カテゴリのタグページ／ナビを最終整備 → sitemap 更新
6. 第2弾投入後あたりで Search Console のインデックス状況・流入を確認し、**第3弾投入後に AdSense 再申請**

### 完了後の到達点

- 記事数 16 → **31本**、未露出だったタグを**7系統のカテゴリとして可視化**（一覧ページ・ナビ・sitemap対応）
- 「単一機能ツール＋1テーマ」から「育児休業給付金の総合情報サイト＋判定ツール」へ位置づけが変わる
- 2025年新設給付（出生後休業支援・育児時短就業）と2025年延長改正のカバー＝鮮度・独自性の証明

## E-E-A-T 補強（並行タスク・YMYL必須）

- 各記事に著者名・最終更新日・出典を明示（既存の注釈リンク方式を継続）
- About に運営者の制度理解の根拠（一次資料に基づく旨）を補足。可能なら社労士監修の検討
- 「情報の正確性」運用ポリシー（改正時の更新方針）を About か専用ページに明記
