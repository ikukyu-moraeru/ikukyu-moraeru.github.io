# write-guide-article

育休もらえる？（育児休業給付金の判定ツール）のガイド記事を、**引き(=読み始めの数行で離脱させない)** と **読みやすさ** を両立させつつ、YMYL（お金×公的制度）として正確・誠実に書くためのスキル。

## 必読（書く前に必ず読む）

- `docs/article-writing-task.md` … 出力フォーマット・運用・禁止事項。**最優先で従う**。
- `docs/article-plan.md` … 各記事の検索意図・見出し・要点。
- `Rule.md` … 制度の事実と一次情報URL（出典はここから引く）。
- `src/domain/*.ts` … 判定ロジック。**記事の数値・主張はこれと矛盾させない**。

## 引きの作り方（このスキルの核）

固い「結論から言うと〜」の連発ではなく、**読者の実感から入って、すぐ核心へ**落とす。

1. **書き出し候補を2〜3案出してから選ぶ**。型の例:
   - 読者の思い込みを名指しする：「週5正社員じゃないから対象外だろう——もったいない誤解です。」
   - 損得を一文で立てる：「同じ5日の休みでも、有給か無給かで受給可否が変わります。」
   - よくある誤情報を否定する：「『出産前まで遡れる』は不正確です。」
   - 数字で意外性：「月11日。これは思ったより低いハードルです。」
2. **最初の段落で“この記事で何が分かるか”を体感させる**。前置き・自己紹介・「本記事では〜を解説します」は書かない。
3. **読者が次に欲する順に並べる**（beat-by-beat）。各H2の終わりで次の疑問が自然に立つように。「で、自分はどうなの？」が湧いたところでツール導線へ。
4. **見出しはコロン多用や体言止めの羅列を避け**、問い or 結論で立てる：「11日に届かない月は『80時間ルール』で救われる」。

## 読みやすさ（日本語トーン）

`~/.claude/skills/write-tech-blog/skill.md` の「AI文体回避」を踏襲。要点:

- 冒頭の問いかけ（「〜したことはありませんか？」）禁止。事実から入る。
- 説明付き箇条書き・表の多用を避け、**段落で文脈を作る**。箇条書きは並列が本当に効く所だけ。
- 「いかがでしたか」「格段に」等の薄い定型・感想を入れない。
- 同じ言い回しの反復を避ける（「〜が効いてきます」等の癖に注意）。
- 一文を長くしすぎない。一人称は使わない。です・ます調で統一。

## YMYL ガードレール（引きと両立させる線引き）

- **煽り・誇張・断定で引かない**。「絶対もらえる」「裏ワザ」は禁止。引きは“具体と意外性”で作る（数字・誤解の訂正・損得）。
- 数値・要件は `Rule.md`／`src/domain` と一致。最終判定は一次情報（ハローワーク）へ誘導。
- 出典は**本文中のインライン注釈**で主張のすぐ横に置く（下記）。記事末の巨大な出典ブロックは作らない。
- E-E-A-T／AdSense「有用性の低いコンテンツ」を壊さない。水増ししない。

## 出力フォーマット（site 固有）

1記事 = `content/guide/<slug>.md`。frontmatter は `docs/article-writing-task.md` の通り（title/description/slug/date/updated/tags/related/draft）。

- **インライン注釈（出典）**: `{{ラベル|URL}}` で主張の直後に置く。例:
  `…12か月以上あること{{厚労省パンフ2025改訂版 p.10|https://www.mhlw.go.jp/content/11600000/001461102.pdf}}。`
  URLなしの補足は `{{補足}}`。小さなグレーで表示される（実装は scripts/build-guide.mjs / public/guide.css）。
- **ツール導線**: 本文中は `/`、関連記事は `/guide/<slug>/`。記事末のCTAボタンはビルドが自動付与するので本文に書かない。
- **related / 本文リンク**: 既に存在する記事の slug のみ（未執筆を指すと404）。
- 免責文・著者情報・末尾CTAはビルドテンプレートが自動付与（本文に重複して書かない）。

## 確認

- `pnpm build`（`pnpm dev` ではガイドは出ない）→ `pnpm preview` → `/guide/<slug>/`。
- ビルド後コンソールに「記事 N 本…生成」が出れば取り込み済み。

## 仕上げのセルフチェック

- [ ] 書き出しの2〜3行で「自分ごと」と思わせ、前置きゼロで核心へ入っているか
- [ ] 各H2の終わりで次の疑問が立ち、ツール導線へ自然につながるか
- [ ] 説明付き箇条書き・表に逃げず、段落で読ませているか
- [ ] 煽り・断定なし。引きは数字／誤解の訂正／損得で作っているか
- [ ] 主張の横に `{{…|URL}}` 注釈で出典があり、数値が `src/domain` と一致するか
- [ ] AI文体（問いかけ冒頭・薄い感想・同語反復）が無いか
- [ ] related と本文リンクが既存 slug のみか
